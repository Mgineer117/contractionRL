# Car policy parameter landscapes

`scripts/skrl/parameter_landscape.py` evaluates existing compact structured-control checkpoints with state `(x, x*, xi)`. Pass their archived repository snapshot with `--source-root`; historical policies must retain their original feature and reference-generator semantics.

The evaluator saves a 31x31 return surface through two orthonormal Gaussian directions, plus central finite-difference curvature along 32 further unit directions at absolute parameter distances 0.1, 0.3 and 1.0. Both methods use the same directions, absolute L2 distances, evaluation seed and first 64 scenarios from one persisted bank. All active mean-control weights and biases are included; exploration variance, metric, critic and buffers are fixed.

The common return is negative normalized tracking-error AUC over 15 seconds. This keeps the objective identical when comparing identity-reward PPO with CCM-reward C2RL-PPO. Failed episodes retain an absorbing box-diagonal tracking-error penalty for the remaining horizon; completion masks are saved separately. Clipping, wrapping and termination can introduce kinks, so finite-difference curvature is a scale-dependent local measurement.

```bash
python -u scripts/skrl/parameter_landscape.py --source-root /path/to/archived/code --checkpoint ppo /path/to/ppo/checkpoints/agent_500000.pt --checkpoint c2rl_ppo /path/to/c2rl/checkpoints/agent_500000.pt --bank /path/to/evaluation_bank.npz --output /path/to/new/results
```

Each checkpoint needs its original `../params/agent.yaml`. The output directory must be new. Defaults use four CPU threads and batch 16 parameter settings. The script checks identical parameter layouts, repeatability, archived actor action parity, and center consistency before accepting its results.

Outputs include PNG/PDF surfaces and curvature distributions, raw episode returns, completion masks, directions, center parameters, configuration/provenance, paired curvature standard errors, a concise report and progress CSVs. Place original W&B evaluation histories in `<output-parent>/<method>_training_history.json` with `rows` containing `global_step` and `Evaluation/Stability/auc_mean` to include the convergence panel. These histories provide context and use their original evaluation stream.

This follows the two-direction slice idea of [Li et al. (2018)](https://papers.nips.cc/paper/2018/hash/a41b3bb3e6b050b6c9067c67f663b915-Abstract.html). These are unit-direction slices, without filter normalization. Directional curvature does not estimate the Hessian spectral norm or conditioning, and a flat slice does not establish good performance or full-space flatness. The present comparison uses existing 256x256, 500,000-step checkpoints from training seed 42.

## Early reward comparison

`run_early_landscape.py --root <prepared-replay-directory> --phase train` performs GPU preflight and a matched 100,000-step PPO/C2RL replay. A dependent CPU job uses `--phase analysis` for the reward-landscape analysis. The prepared directory contains the archived source, original configurations and frozen metric, a shared fresh initialization, and `plan.json`. `early_landscape_replay.py` saves snapshots at initialization and every 10,000 steps outside the normal pruning directory. Environment draws, Gaussian action draws and optimizer draws use separate random streams; policy-dependent episode resets can still diverge. Both methods must accept PPO updates and match initial model/scenario hashes before the full replay proceeds.

For CPU placement, `--phase all --training-device cpu` runs validation, training and analysis in one allocation. The CPU retry retains the same source, initial weights, metric and target budget, with separate paths from the GPU attempt.

`early_reward_landscape.py` evaluates both identity and CCM energy-decrement rewards on each perturbed policy's same stochastic trajectories, using fixed references, bounded gusts and Gaussian draws. It reports discounted return with gamma 0.99 and common tracking AUC. Geometry evaluation uses float64 to reduce cancellation; training uses the archived float32 implementation. Return scales are calibrated once using each objective's RMS return at the shared initial policy and remain fixed throughout analysis. Raw and normalized curvatures are retained. Reward returns stop at first episode end; AUC retains the absorbing failure penalty. Completion masks are saved without dropping cases.

The predeclared curvature times are 0, 10k, 20k, 40k, 60k, 80k and 100k. Surface times are 0, 20k, 40k and 60k. Each surface figure crosses policy center (PPO/C2RL) with reward objective (identity/CCM). These measurements test whether a geometry difference precedes or accompanies faster learning; they do not assume the outcome or establish a general causal effect from one seed. PPO's clipped-surrogate geometry can also differ from rollout-return geometry.

The analysis first produces an explicitly preliminary 7x7 preview at the four surface times with four curvature directions, saving it in `analysis-preview`. It reuses these exact evaluations while filling the full predeclared grids and 32 directions in `analysis`. Figures update after each checkpoint pair. `landscape_evolution_identity` and `landscape_evolution_ccm` use common directions and one vertical/color scale across training times, objectives and methods. These are moving local slices around the saved policies; each checkpoint's exploration variance is held fixed during its slice.

To isolate the reward definition, run `plot_reward_landscape_comparison.py --input <analysis-directory> --output <new-directory>` on saved results. Columns compare PPO's Euclidean energy-decrement reward and C2RL's metric energy-decrement reward at exactly the same policy parameters and exploration variance. Each surface subtracts its central return and uses the fixed initial RMS calibration. Vertical and color limits match within each checkpoint figure; they can differ between checkpoint figures. The curvature plot compares both rewards along each policy trajectory, retaining every tested perturbation size. Raw and normalized curvature values and source hashes are saved alongside the figures; no new rollouts are performed.

`reward_landscape_scan.py --root <prepared-replay-directory> --output <new-directory>` evaluates a second, fixed plane: the PPO 0-to-20k displacement and the orthogonalized C2RL 0-to-20k displacement. These directions are selected from training paths, without inspecting reward-surface outcomes. It uses the same 64 scenarios, archived code, checkpoint exploration variances and initial-RMS calibration as the original evaluator. One 25x25 grid spans coefficients from -20 to 20, providing nested radius-5/10/20 maps at unchanged spacing (7/13/25 points per axis). This is a coarse overview, supplemented by the original fine random-plane maps and 0.1-spaced one-dimensional cuts within radius 1. It does not establish the absence of features between grid points. Checkpoint-center returns must reproduce the original evaluator.

`plot_reward_landscape_diagnostics.py --input <scan-or-original-analysis> --curvature-input <full-original-analysis> --output <new-directory>` renders paired contours, centered normalized reward-difference maps, overlaid one-dimensional cuts, raw-versus-normalized profiles, episode-completion controls, and paired curvature distributions for every saved perturbation size. Within each contour column, reward maps share color limits; across columns, read the labeled color bars. Difference-map ranges and slice y-ranges are local to each panel. Curvature is recomputed exactly from saved paired episode returns. Raw files, source hashes, grid statistics, direction counts and normalization constants remain available for verification. With fixed objectives and a frozen metric, the landscapes themselves are fixed; checkpoint plots sample different neighborhoods.
